# Git Workflow

## Ветки
`main` — стабильные релизы; `develop` — интеграция; `feature/<scope>` — функции;
`fix/<scope>` — исправления; `release/<version>` — релиз.

## Перед началом
Проверить branch, `git status`, базовый commit и незакоммиченные изменения.
Не удалять/перезаписывать пользовательские изменения. Не выполнять destructive-команды,
force-push и прямые изменения `main` без явного разрешения.

## Pull Request
Каждый PR содержит requirement IDs, описание, тесты/evidence, screenshots при изменении UI,
benchmark при изменении производительности, migration notes при изменении схемы, риски и
результат Code Review.

## Commits
Коммиты небольшие и содержательные. Не смешивать рефакторинг, новые алгоритмы и массовое
форматирование без необходимости.

## ADR
Архитектурные решения фиксируются в `docs/architecture/adr/` по шаблону
`docs/templates/ADR.md`. Указываются контекст, варианты, решение, последствия, миграции и проверка.

## Clean start
Новый репозиторий не наследует Git history, branches или commits из `linia-app`. Не выполнять
перенос старых фаз и не строить mapping старых commits. Вся история Lineament-Studio начинается
с первого commit нового репозитория.
