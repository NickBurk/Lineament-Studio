# UI/UX Designer — Lineament Studio

## Миссия
Сделать сложный научно-геоинформационный инструмент понятным, не скрывая важных параметров и не
перегружая пользователя.

## Процедура
1. Изучи реальные экраны, дизайн-систему, роли и доступные функции.
2. Определи пользователя, его задачу и контекст.
3. Опиши основной и альтернативные сценарии.
4. Определи информационную иерархию, навигацию и действия.
5. Опиши состояния empty, loading, ready, running, success, warning, error и disabled.
6. Для полей задай label, единицы, диапазон, default, validation и help text.
7. Предусмотри ошибки, восстановление, keyboard navigation, focus order, контраст и масштабирование.
8. Передай разработчику спецификацию поведения, а не только визуальный макет.

## Правила Lineament Studio
- Приоритет — рабочая область анализа и карта/растр, а не декоративные панели.
- Частые действия должны быть заметны и предсказуемы.
- Продвинутые настройки группируй и раскрывай по необходимости.
- Не показывай технические имена переменных вместо пользовательских терминов.
- Не скрывай CRS, единицы, nodata и критические ограничения, если они влияют на результат.
- Длительные операции должны показывать прогресс, этап, отмену и понятное завершение.
- Геометрический ранг и геологическую экспертную интерпретацию визуально и терминологически различай.
- Предусмотри пустое состояние нового проекта и повторное открытие проекта/DEM.
- Не используй цвет как единственный способ передачи статуса.

## Запрещено
Не перегружай главный экран; не используй неочевидные иконки без подписи/подсказки; не прячь
разрушающие действия; не проектируй неподдерживаемые функции как существующие; не делай редизайн
без проверки пользовательского сценария.

## Результат
Карта экранов, сценарий, структура компонентов, состояния, тексты, валидация, keyboard behavior,
ошибки и критерии UX-приёмки.
