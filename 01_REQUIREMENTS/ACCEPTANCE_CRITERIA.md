# Acceptance Criteria

## Общие правила
Функция принимается только при выполнении применимых пунктов:
1. Есть рабочая реализация, а не UI-заглушка.
2. Входные параметры валидируются.
3. Ошибки обрабатываются и объясняются.
4. Выходные данные имеют документированную схему.
5. CRS, transform, units, NoData и provenance сохранены корректно.
6. Есть unit- и integration-тесты.
7. Есть regression-тест критического сценария.
8. Есть документация параметров.
9. Есть пример запуска.
10. Есть отчёт с командами, результатами и evidence.
11. Независимое review закрывает все P0/P1 findings.

## Given / When / Then

### AC-PROJ-001 — создание и повторное открытие
- Given: приложение запущено и пользователь выбрал каталог проекта.
- When: пользователь создаёт проект, импортирует DEM, сохраняет, закрывает приложение и запускает его снова.
- Then: проект открывается через `project.lspx`, DEM/слои/результаты восстанавливаются, ошибки источников отображаются явно.

### AC-PROJ-002 — отсутствующий внешний DEM
- Given: проект с `storage_mode=reference`, исходный DEM перемещён или недоступен.
- When: пользователь открывает проект.
- Then: приложение сохраняет доступ к остальным данным, показывает missing-source state и предоставляет Locate/Relink без молчаливой подмены.

### AC-DATA-001 — Preflight
- Given: GeoTIFF с известными CRS, transform, dimensions, resolution, dtype и NoData.
- When: пользователь запускает Preflight.
- Then: все метаданные показываются и сохраняются; некорректные/неизвестные значения не исправляются автоматически.

### AC-DATA-002 — CRS и единицы
- Given: DEM в географической CRS и метрический параметр обработки.
- When: пользователь запускает операцию, требующую расстояние в метрах.
- Then: приложение блокирует некорректное прямое применение или выполняет явно выбранное корректное преобразование.

### AC-JOB-001 — отмена
- Given: длительная задача выполняется Worker.
- When: пользователь нажимает Cancel.
- Then: отмена происходит на безопасной границе; GUI остаётся доступным; неполные файлы не публикуются как финальные.

### AC-REV-001 — независимая разметка
- Given: два эксперта имеют отдельные Annotation Sets для одного набора кандидатов.
- When: оба набора импортируются и сравниваются.
- Then: исходные наборы остаются неизменными, конфликты видны, Consensus Set создаётся отдельной подтверждённой операцией.

### AC-DS-001 — spatial split
- Given: набор chips из пространственно соседних областей.
- When: создаётся Train/Validation/Test split.
- Then: используется пространственное разделение; соседние chips не распределяются случайно между train и test без явного override и предупреждения.

### AC-OFF-001 — offline-first
- Given: сеть отключена.
- When: пользователь создаёт проект, открывает локальный DEM, запускает локальный pipeline и экспортирует результат.
- Then: основной сценарий работает без внешнего API/LLM/GEE/OSM endpoint.

### AC-REL-001 — чистая Windows
- Given: чистая целевая Windows без системного Python и QGIS.
- When: устанавливается portable build или installer.
- Then: приложение стартует, открывает `.lspx`, читает DEM, выполняет минимальный pipeline и экспортирует результат.

### AC-SEC-001 — небезопасный project path
- Given: manifest содержит внутренний путь с path traversal.
- When: проект открывается.
- Then: путь отклоняется, файлы вне каталога проекта не читаются и не изменяются.

## Критические регрессионные сценарии
DEM при первом и повторном запуске; project reopen; Reference/Copy; missing-source relink;
отмена; Worker failure; export round-trip; CRS; независимая разметка; `.lspx` migration.
