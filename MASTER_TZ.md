# Lineament Studio — Master Technical Specification

## 1. Назначение
Lineament Studio — автономная исследовательская GIS-платформа для обнаружения, анализа,
экспертной проверки и документирования линейных форм рельефа и потенциальных структурных
элементов по DEM. Программа поддерживает поиск кандидатов на тектонические разломы и другие
линейные структуры, но не объявляет обнаруженную линию доказанным разломом.

## 2. Цели
1. Поиск кандидатов на тектонические разломы и нарушения.
2. Региональный структурно-тектонический анализ.
3. Предварительное выделение перспективных участков для дальнейшей геологической оценки.
4. Анализ трещиноватости и структурных систем по доступным данным.
5. Обнаружение линейных форм рельефа.
6. Подготовка экспертно размеченных датасетов.
7. Научное сравнение алгоритмов и параметров.

## 3. Продуктовая модель
- **Lineament Studio Desktop** — самостоятельное Windows-приложение в комплектной поставке.
- **Lineament Studio QGIS** — отдельный Processing Provider / plugin, использующий совместимый Core Runtime.
- **GEE Adapter** — дополнительная интеграция с Google Earth Engine, не обязательная для автономной работы.

## 4. Принципы
DEM-first; One Core; Offline-first; Human-in-the-loop; Reproducibility; Resource-aware;
Scientific transparency; Data integrity; Provenance-first.

## 5. Основной сценарий
Создать проект → импортировать DEM → Preflight → preprocessing → Single/Ensemble →
vectorization → matching → LSM_DEM → structural analysis → экспертная проверка →
Dataset/ML → отчёт и экспорт.

## 6. Технологии — предварительная базовая линия
Python 3.11; PySide6/Qt; GDAL/PROJ/Rasterio; NumPy/SciPy; OpenCV; Shapely; SQLite;
GeoPackage; GeoTIFF/COG; Scikit-learn; PyInstaller Onedir; Inno Setup.
Точные версии фиксируются после проверки совместимости и лицензий.

## 7. Pipeline
`DEM → Preflight → Preprocessing → Multi-scale → Detection → Filtering → Vectorization →
Ensemble Matching → LSM → Structural Analysis → Expert Review → Export`

## 8. LSM
LSM_DEM — карта пространственной поддержки только по DEM-свидетельствам. Группы:
Directional Support, Detector Agreement, Scale Persistence, Morphometric Support.
Начальные веса и радиусы — инженерные стартовые настройки, а не научно подтверждённые
константы. Их пригодность оценивается benchmark/ablation study.

## 9. Классификация
Geometric Ranking, User-defined Ranking и Geological Order — три раздельные системы.
Геометрический ранг не является геологическим порядком. Геоморфологические гипотезы должны
содержать альтернативные объяснения и ограничения исходных данных.

## 10. Экспертная работа
Эксперты работают в независимых Annotation Sets. Исходный кандидат не перезаписывается.
Consensus создаётся как отдельный производный набор. Принятие линии означает принятие кандидата
для дальнейшей интерпретации, а не доказательство разлома. Отсутствие метки не является
отрицательной меткой.

## 11. AI/ML
Базовая работа не зависит от LLM, GPU или внешнего API. Rule-based Smart Workflow и классический
локальный ML доступны offline. AI предлагает параметры, очередь проверки и QA-подсказки;
не подтверждает геологические структуры автоматически.

## 12. Производительность
Целевой Standard-профиль — ноутбук с 16 ГБ RAM и встроенной графикой. Блочная обработка
обязательна для больших растров. Бюджет Worker до 6 ГБ и tile 1024×1024 — стартовые
инженерные ориентиры, требующие benchmark, а не гарантированные лимиты.

## 13. Хранение
Проект — папка с главным файлом `project.lspx` (UTF-8 JSON manifest), SQLite-каталогом,
GeoPackage, GeoTIFF и структурированными каталогами. `project.lspx` — точка входа и источник
проектной конфигурации; `project.sqlite` — каталог сущностей и транзакционных метаданных.
DEM — Reference или Copy. Backup — ручной. Сохранение и миграции версионированы и безопасны.

## 14. Научные ограничения
Не называть все линии разломами; не трактовать stability/support_score как вероятность;
не назначать геологический порядок только по длине; не считать отсутствие линии доказательством
отсутствия структуры; не считать зависимые детекторы независимым подтверждением; не выдавать
эвристику за валидированный метод.

## 15. Приоритеты
P0 — работоспособный исследовательский MVP; P1 — полноценная версия 1.0; P2 — последующее
развитие; P3 — необязательные расширения. Профильные документы содержат требования, критерии
проверки и открытые вопросы.


## 16. Clean repository baseline
Разработка ведётся в новом GitHub-репозитории `Lineament-Studio` с нуля. Код, Git history,
ветки, commits, tests и build artifacts из `linia-app` не переносятся и не используются.
Переносятся только согласованные продуктовые решения и документация. Первый инженерный этап —
Repository Bootstrap & Architecture Baseline, затем Core Contracts. Импорт ранее созданных
пользовательских проектов не предполагается без отдельного требования.
