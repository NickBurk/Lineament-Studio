## Компоненты и зависимости

```text
lineament_desktop (PySide6) ──┐
                             ├── Job Client ── JSON/JSONL ── lineament_core.worker
QGIS Processing adapter ─────┘                                     │
                                                                    ▼
                                                          Core application
                                         ┌──────────────────┼─────────────────┐
                                         ▼                  ▼                 ▼
                                    Core domain      Algorithm Registry   Data Engine (port)
                                                                              ▲
                                                                              │ implements
                                                                     GIS/Raster Engine
                                                                    + Project Storage
                                                                    + SQLite Catalog
```

| Компонент | Ответственность | Граница |
|---|---|---|
| Core Domain | Модели, value objects и инварианты. UUID, ссылки и единицы в явном виде | Python 3.11, стандартная библиотека. Без GUI, IO и нативных геотипов в публичных моделях |
| Core Application | Use cases, порты данных, правила публикации результата и orchestration задания | Зависит от Domain и собственных портов. Worker связывает порты с адаптерами |
| Algorithm Registry | Единственный каталог допустимых операций и версий. Валидация схем параметров и дескрипторов | Явная регистрация. Никаких пользовательских import paths или загрузки исполняемого кода из manifest |
| Data Engine | Порты и координация ingest, preflight, CRS, метаданных и валидации результатов | Application использует единый набор портов. Infrastructure предоставляет реализации |
| GIS/Raster Engine | Чтение растра окнами, драйверы, преобразования CRS, обработка геометрий и spatial IO | Реализация портов Data Engine. Доступ к GDAL/Rasterio/PROJ/GEOS через выбранный runtime |
| Project Storage | Открытие папки, `.lspx`, разрешение путей, staging, публикация и восстановление | Критические записи координируются через этот слой. Артефакт становится доступен после проверки и фиксации ссылки |
| SQLite Catalog | Связи, идентификаторы, jobs, журнал и транзакционные метаданные | Реализует порт каталога. GeoPackage хранит геометрию отдельно. DB-соединения ограничены процессом/потоком владельца |
| Job Manager | Одна машина состояний в Application, переходы и проверки отмены. Durable state добавляется вместе с каталогом | Job Client управляет дочерним процессом и отображает подтверждённые события. Запись статуса принадлежит Core |
| IPC / Worker | Versioned request/events, выполнение зарегистрированной операции, исключения на границе процесса | Worker является composition root. UI/QGIS используют общий лёгкий клиент и контракт |
| Desktop / QGIS | Представление и действия пользователя, преобразование параметров интерфейса в контракт, загрузка результата | Desktop — PySide6. QGIS — отдельная упаковка и чистый профиль. Общий Core Worker |
| OSM / GEE | Получение внешних данных с provenance | Отдельные необязательные для локального запуска адаптеры. Локальный импорт OSM входит в профиль OSM |
| Tests / Packaging | Проверка контрактов, данных, научных методов, сборки и поставки | CI для чистого Core отдельно от Windows Bundle и QGIS |

Core Application импортирует Domain. Infrastructure реализует порты Application и опирается на Domain. Worker собирает приложение, Infrastructure и IPC. Модели транспорта лежат в `lineament_core.contracts`, общий stdlib-клиент — в будущих `lineament_core.adapters.ipc_client`. Desktop и QGIS используют этот клиент, сохраняя собственную интеграцию с event loop/feedback. QGIS-адаптер поставляет минимальную совместимую клиентскую часть из того же исходного кода. Необходимость отдельного артефакта для клиента оценивается после OQ-02. Импорт `lineament_core` и контрактов остаётся доступным в чистом Python.

Отдельный процесс вычислений уже выбран (DEC-A03). Размещение Job Manager и форма transport binding предложены в ADR-0002. Карта требует ограниченного оконного чтения. Канал preview/render и владелец дескрипторов остаются открытыми до прототипа. Любое чтение для Desktop использует общие правила Data Engine. [API Contracts](../../02_ARCHITECTURE/API_CONTRACTS.md) · [ADR-0002](adr/ADR-0002-IPC-AND-JOB-LIFECYCLE.md)

## Состояние, данные и восстановление

1. Клиент проверяет версию Worker и передаёт job manifest. Worker валидирует envelope, операцию и payload до IO, затем запускает use case.
2. Job Manager координирует стадии и отмену. Worker применяет безопасные точки отмены и отдаёт события. Прогресс идёт по фактическим этапам. Живой клиент располагает диагностикой сбоя процесса даже при оборванном потоке событий.
3. Вычисления пишут staging-артефакты. Project Storage проверяет геометрию, схемы, метаданные и ожидаемые контрольные суммы. Catalog публикует ссылки и финальный статус после проверки доступности результата. Идемпотентность и reconciliation закрываются в OQ-24/OQ-26 до реализации данных.
4. `project.lspx` остаётся точкой входа и источником проектной конфигурации. `project.sqlite` хранит каталог и транзакционное состояние. Пространственные файлы хранят полезную нагрузку. Для пересечения по asset records и журнала сохранения предложен ADR-0003. [ADR-0001](adr/ADR-0001-LSPX-PROJECT-MANIFEST.md) · [ADR-0003](adr/ADR-0003-PROJECT-DATA-OWNERSHIP.md)

Domain хранит логические ссылки, UUID, enums и метаданные с указанными единицами. Состояние `missing` для Reference определяется при проверке файлов. Relink — явная операция с проверкой CRS, размеров, transform и checksum, аудитом и подтверждением при изменении содержимого. Copy сохраняет источник и проверяет свободное место. Для путей внутри проекта проверяются нормализация и реальное разрешение с учётом Windows reparse points. План проверок включает сбой на границе транзакции, несовпадение project ID, повторное открытие, повреждённый или недоступный файл и повтор после отмены. [Project Storage](../../04_DATA/PROJECT_STORAGE.md) · [Metadata Schema](../../04_DATA/METADATA_SCHEMA.md)

## Независимые версии

Версия дистрибутива следует PEP 440 в packaging-метаданных. Независимые версии IPC, формата `.lspx`, SQLite schema, параметров и результатов алгоритма проверяются на границе соответствующего владельца. Для несовместимых IPC изменений требуется major, для совместимых добавлений — явно проверенные правила minor. Изменение математического поведения меняет algorithm version и требует регрессии/benchmark. Изменения формата данных требуют правил чтения, записи и миграции с планом восстановления. До принятия ADR формат примеров в спецификации служит входом для проектирования. [Core Architecture](../../02_ARCHITECTURE/CORE_ARCHITECTURE.md) · [План Phase 1](../PHASE_1_CORE_CONTRACTS_PLAN.md)
