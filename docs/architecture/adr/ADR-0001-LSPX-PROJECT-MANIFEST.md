# ADR-0001: Главный файл проекта `project.lspx`

- Статус: Accepted (architect-selected baseline; не является заявлением о ранее данном user approval)
- Дата: 2026-11-27
- Авторы: Project Architecture
- Связанные требования: PROJ-001, PROJ-002, PROJ-003, PROJ-006, PROJ-007, PROJ-008

## Контекст
Исходная мастер-документация v0.1.0 описывала folder-based project с JSON manifest, но называла
главный manifest `project.json`. Пользовательский Skills Pack v1.0 требует, чтобы проект хранился
в каталоге с главным файлом `.lspx`. Формулировки конфликтовали по имени главного файла.

## Решение
Проект остаётся каталогом. Главный файл называется `project.lspx` и является UTF-8 JSON manifest
с `format_id`, `format_version` и `schema_version`. `project.sqlite` — каталог сущностей/связей/
событий. GeoPackage и GeoTIFF хранят пространственные данные отдельно. `project.json` не используется как главный файл целевой схемы. Импорт ранее созданных
пользовательских проектов из иных форматов не входит в базовый scope и требует отдельного
решения пользователя и отдельной спецификации импорта.

## Рассмотренные альтернативы
1. Оставить `project.json` — отклонено, так как противоречит Skills Pack.
2. Сделать `.lspx` ZIP/container — не выбрано: исходная архитектура уже использует JSON manifest,
   а Skills Pack не требует контейнерного формата.
3. Сделать `.lspx` JSON manifest — выбрано как минимальное согласованное решение.

## Последствия и риски
Точка входа проекта становится однозначной; появляется отдельная версия формата проекта.
Нужно тестировать manifest schema, path resolution, save/reopen и round-trip. Backward compatibility
с форматами, не специфицированными для нового продукта, не заявляется.

## Миграции и совместимость
Миграции между версиями нового `project.lspx` формата выполняются явно и версионируются.
Импорт из внешних/старых форматов — отдельная будущая функция, не предпосылка создания нового
репозитория. Если она будет утверждена, импорт не должен изменять исходные файлы и должен иметь
preview, журнал, проверку и rollback.

## Проверка корректности
Schema validation; path traversal tests; internal/external DEM tests; missing-source/relink;
checksum drift; save-close-reopen; fault-injection; round-trip на чистой Windows.
