# Accessibility and State Matrix — Desktop

**Статус:** критерии UX blueprint для будущего приложения. Проверки требуют реализованного GUI; это не отчёт об уже выполненной доступности.

## 1. Доступность ввода и фокуса

- Все команды доступны клавиатурой и имеют видимую подпись. Hover-only controls запрещены.
- Предлагаемый focus order главного окна: title/project commands → workspace navigation → workspace content (слои/карта) → context inspector → нижние Tasks/Warnings/Logs. Tab движется по логическому порядку; `Shift+Tab` проходит его обратно. Панель, свернутая пользователем, исключена из tab order; при раскрытии получает понятную точку входа.
- Внутри длинного списка слоёв/задач используется предсказуемая навигация стрелками; Enter/Space активируют строку/visibility. Для карты предусмотрены клавиатурный pan/zoom и отдельный список доступных объектов/слоёв; интерактивность карты не является единственным способом добраться до её содержимого.
- После закрытия диалога фокус возвращается инициировавшей команде. При ошибке фокус ставится на заголовок сообщения/первое действие, но не теряется в уничтоженном виджете. После удаления/скрытия выбранного элемента фокус переходит к ближайшему соседу или на контейнер с объявлением.
- В каждой подсказке и меню рядом с командой показывается shortcut; одинаковые глобальные shortcuts не переопределяются в отдельных workspace без ясного контекста.

Предлагаемые стандартные shortcuts (до реализации проверить конфликт Qt и платформы): `Ctrl+N` New Project; `Ctrl+O` Open Project; `Ctrl+S` Save; `Ctrl+Shift+S` Save As/Copy Project если соответствующий use case существует; `Ctrl+1…9` только для первых закреплённых workspace при наличии пользовательского списка; `F6` переход между панелями; `Esc` закрытие transient menu/dialog или отмена выбора, но не молчаливая отмена задачи. Горячая клавиша отмены task отображается только когда действие доступно. `Ctrl+W` закрывает проект, затем применяет unsaved/task guard.

## 2. Контраст, цвет и текст

- Проверять WCAG 2.2 AA для обычного текста: контраст foreground/background не ниже 4.5:1; крупного текста и графических границ/индикаторов UI — не ниже 3:1. Для важных элементов карты валидировать контраст на светлом, тёмном и разноцветном фоне.
- Любой статус передаётся как текст плюс форма/иконка или паттерн: `Ready`, `Warning`, `Unavailable`, `Running`, `Failed`; зелёный/красный/янтарный/серый не единственный канал. Disabled состояние остаётся читаемым и имеет объяснение для ключевой команды.
- Не использовать только оттенки красного/зелёного для классов и слоёв. Для кандидатов/границ использовать разные типы линий/маркеры и легенду; пользователь может менять палитру, не теряя семантику.
- Статус предупреждения и ошибки объявляется доступной технологией чтения экрана без перехвата фокуса на каждое обновление прогресса. Обновления процентов сгруппированы и не озвучиваются чаще разумного интервала.
- Карточки ошибок используют обычные слова и конкретные действия; технический код и дополнительная диагностика доступны отдельно и копируются без пользовательских путей/секретов в общий журнал.

## 3. Масштабирование и High DPI

- Масштабирование окна: 100%, 125%, 150%, 200%; пользовательский масштаб текста/интерфейса доступен независимо от масштаба карты. UI layouts используют logical px и поддерживают fractional/DPI scaling, не обрезая кнопки/текст.
- Проверить Windows monitor scale 100%→150% при перемещении окна; геометрия hit target, иконок и разделителей не должна теряться. Рекомендуемый минимум интерактивной цели — 24×24 CSS/logical px (или достаточный отступ между компактными объектами); частые кнопки/controls целиться в 32×32 logical px.
- Увеличение текста до 200% не обрезает имена слоя, CRS, ошибки, labels и диалоговые кнопки; в таблицах длинные значения доступны через wrapping/tooltip/инспектор, а не исчезают.
- Zoom карты отдельный от UI scale. Увеличение интерфейса не должно автоматически читать весь большой растр или менять extent.

## 4. Shortcut и взаимодействия карты

| Контекст | Клавиатурное поведение | Подсказка |
|---|---|---|
| Workspace navigation | Стрелки/Tab по именованным разделам; Enter активирует | Имя и shortcut видимы в label/tooltip |
| Layer list | Стрелки выбирают слой; Space переключает visibility; Enter открывает инспектор | Строка содержит имя, тип и текстовый статус |
| Canvas | +/- zoom, стрелки pan (предложение, проверяется конфликтом); Home fit-to-visible-layers; Tab к списку объектов | Canvas имеет доступное имя, CRS и инструкцию |
| Swipe | Стрелки меняют divider дискретно; Home/End — начало/конец; range control имеет имя и текущее значение | Например: «Swipe position, 50 percent» |
| Task Manager | Стрелки выбирают задачу; Enter открывает детали; Cancel — отдельная именованная кнопка | Название задания, реальный этап, progress state, состояние cancel |
| Modal/error | Tab по действиям, Escape = Cancel только если это безопасно и ясно | Действие по умолчанию не уничтожает и не заменяет данные |

Все сочетания являются проектным предложением до реализации; окончательный список проверяется на Windows, macOS/Linux dev environment и конфликт с Qt/assistive technology.

## 5. State matrix

Применимую ячейку следует реализовать для каждого экрана и операции; `—` значит состояние не имеет смысла именно в этом контексте, а не скрывает отсутствие данных.

| Объект/экран | Empty | Loading | Ready | Running | Success | Warning | Error | Disabled |
|---|---|---|---|---|---|---|---|---|
| Project / Dashboard | Новый проект; объяснение и Add DEM | Чтение manifest с названием проекта и indeterminate indicator | Сводка источников, экспериментов, задач | Обычно summary параллельно задаче | Проект сохранён/создан с undo-appropriate message | Недоступные источники/несохранённые изменения | Невалидный manifest/unsupported schema с recovery | Project command unavailable с причиной |
| Data Workspace | Empty map/list + Add DEM | Copy/metadata/Preflight stage | Список слоёв, viewport, report | Отдельная строка показывает stage | Источник зарегистрирован и прошёл checks | CRS/NoData/unit/integrity uncertainty | unreadable/corrupt/permission error | Import/Run disabled по конкретной причине |
| Map Canvas | Нет слоёв; текст в центре | Первый viewport/CRS transformation | Видимые слои и легенда | Async pan/render только если реально долго | Новый viewport показан | Часть слоёв непроецируема/недоступна | Источник/driver/render failure | Выбор невозможен без selectable content |
| Preflight report | Нет результата до запуска | Этапы реальных проверок | Полная таблица результатов | См. Tasks; не подменять Preflight фальшивым task % | Время и источник отчёта | Флаги с consequence/action | Читаемый диагностический код и retry/remove | Нельзя повторить для удалённого/закрытого источника |
| Task Manager | Нет задач, текстовая empty state | Получение queued job/status из владельца | Очередь/история завершённых | Реальный stage, % или «этап: n из m»/indeterminate; Cancel при поддержке | Completed + артефакты/summary | Завершено с предупреждениями либо warning event | Failed + стабильный error code, retry policy если есть | Cancel недоступен после commit boundary/terminal state |
| Relink dialog | Нет доступного asset, dialog не открыт | Candidate inspection/checksum | Проверки candidate до confirm | Долгий hash может иметь этапы и реальный progress | Ссылка принята, asset available | Checksum mismatch и отдельное явное решение | Incompatible/corrupt candidate | Confirm отключён до совместимости/явного выбора |
| Close Project / App | — | Сохранение/закрытие ресурсов | Нет изменений и задач | Task close decision; wait/cancel согласно утверждённой lifecycle | Закрытие подтверждено | Unsaved changes / active tasks | Save/cleanup failure оставляет окно открытым | Close action disabled только с объяснением состояния |

## 6. Task Manager: настоящие этапы и проценты

Task Manager отображает только состояние от источника операции. Для Core Worker использовать существующие JSONL события `started`, `stage_started`, `progress`, `warning`, `artifact_created`, `stage_completed`, `cancel_requested`, `cancelled`, `failed`, `completed`; `commit_started` отражает границу финализации. Не придумывать дополнительные event names, payloads, progress API или transport. Любая передача новых событий/полей в Core требует Contract Change Request Agent01.

| UI status | Событие/условие контракта | Отображение |
|---|---|---|
| Queued | Desktop локально ожидает запуска; не выдаётся Core как будто `started` | «В очереди», без процента |
| Starting | запуск процесса/handshake на стороне Desktop, если такие этапы доступны | «Подготовка Worker», неопределённый индикатор |
| Running | `started`, затем текущий `stage_started` | Локализованное имя этапа; без stage — «Выполняется» |
| Progress | `progress.percent` | Отображать абсолютный job percent 0–100. Не вычислять % из времени или фиктивного числа этапов. При отсутствии события показывать indeterminate и название этапа. |
| Cancelling | первый `cancel_requested` принят | «Запрошена отмена»; кнопка отключена/«Ожидаем безопасную точку», пока нет терминального события |
| Finalizing | `commit_started` | «Сохранение результата»; cancel disabled по текущим семантикам lifecycle |
| Completed | `completed` после согласованного result | «Завершено», время и доступные artifacts; 100% только если контракт сообщает этот процент или UI выводит отдельно terminal status |
| Cancelled | терминальный `cancelled` | «Отменено», завершённые ранее outputs не выдаются как финальные, если результат не опубликован |
| Warning | активный `warning.warning_code` | Полная текстовая формулировка по каталогу warning codes; задача продолжает работу только если так диктует контракт |
| Failed | терминальный `failed.error_code` либо transport failure | Понятное сообщение, код и диагностика; `Retry` только если операция действительно может быть пересоздана с новым job ID и безопасными данными |

Список этапов берётся из реальных `stage_started` событий выбранного algorithm descriptor; никакой фиксированный DEM pipeline не отображается в любом задании. Если этапов нет, честный fallback — «Выполняется» плюс indeterminate indicator. Частота обновления UI не должна давать ложную точность; сохранить последний event sequence/timestamp для диагностики, скрывая технический шум по умолчанию.

### Закрытие приложения с задачей

До утверждения OQ-23 UX предлагает безопасный вариант: показать активные задачи, их этап, этап commit и последствия; `Keep app open` сохраняет процесс под контролем клиента; `Request cancel and wait` посылает кооперативную отмену, дренирует события до terminal, ждёт завершения child и лишь затем закрывает GUI. Таймаут/принудительное завершение нельзя описывать как успешную отмену; показывать, что состояние требует recovery. Авто-продолжение worker после выхода отсутствует как обещание, пока не реализован и не подтверждён контролируемый lifecycle. Решение о точной политике при закрытии приложения остаётся open и не вводит новый IPC.

## 7. Acceptance matrix для accessibility/state

| ID | Given / When | Then / evidence после реализации |
|---|---|---|
| A11Y-01 | Только клавиатура; пройти главное окно | Все команды и панель доступны, фокус виден, порядок совпадает с 1-м разделом, нет keyboard trap. GUI automation/manual evidence. |
| A11Y-02 | 200% UI scale и High DPI 150% | Нет обрезанного обязательного текста/команд; hit target остаётся различимым. Screenshot + manual check. |
| A11Y-03 | Статусы Ready/Warning/Error отображаются без цвета | По тексту и форме/иконке можно отличить состояния в grayscale и color-vision simulation. Contrast audit. |
| A11Y-04 | Screen reader получает progress updates | Название задачи/этап/состояние объявлены; частые проценты не создают flood. NVDA/Windows manual check. |
| STATE-01 | Каждый ключевой объект в каждом применимом состоянии | Видны смысл состояния, следующий безопасный шаг, действия и фокус; проверить matrix на GUI state tests. |
| STATE-02 | Core не сообщает progress | Task показывает stage/indeterminate, не выдумывает процент. Event replay assertion. |
| STATE-03 | Закрытие при accepted cancellation | Окно не объявляет задачу cancelled до терминального события/выхода Worker. Lifecycle integration test. |

Значения WCAG/масштабирования здесь UX критерии будущей реализации, не evidence фактического соответствия.
