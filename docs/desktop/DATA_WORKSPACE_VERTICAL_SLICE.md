# Data Workspace — вертикальный сценарий

**Статус:** UX blueprint для review; поведение приложения не реализовано.  
**Трассировка:** PROJ-001–004, PROJ-006–008, DATA-001/002/006–009, UI-001/004, OQ-18, OQ-23.

## 1. Информационная модель экрана

Data Workspace одновременно показывает слои проекта, состояние источника, результат DEM Preflight и карту. Таблица слоёв включает: имя; тип/формат; источник (в проекте или внешний); availability; CRS; состояние Preflight; видимость. Не сокращать ключевые поля до цветного индикатора. Клик по слою синхронизирует canvas selection и inspector. Порядок в списке соответствует порядку отображения; reorder меняет только presentation order.

```text
Data Workspace                                      [Add DEM] [Add layer…]
┌ Layers ──────────────────────────────┐ ┌ Map ───────────────────────────┐
│ DEM North   GeoTIFF  Ready  Visible  │ │                                │
│ Geology     GeoTIFF  Ready  Visible  │ │        viewport                │
│ Faults      GPKG     Ready  Hidden   │ │                                │
└──────────────────────────────────────┘ └────────────────────────────────┘
┌ Preflight / Context ────────────────────────────────────────────────────┐
│ Source policy: Reference | Copy   CRS / resolution / NoData / extent…  │
│ [Open report] [Locate…] [Remove layer…]                                 │
└─────────────────────────────────────────────────────────────────────────┘
```

В узком окне список слоёв и свойства переключаются вкладками; карта остаётся в центре внимания. Добавление слоя не закрывает текущий проект и не меняет исходные данные. Preflight report имеет доступный заголовок, summary предупреждений и полный перечень проверок.

## 2. Создать проект и импортировать DEM

1. `New Project` → имя и родительский каталог → создаётся папка проекта с `project.lspx` как UTF-8 JSON manifest и `project.sqlite` согласно storage specification. Отдельного выбора Project CRS не навязывать, если его нельзя корректно определить из данных; проектный CRS может быть пуст/неизвестен согласно схеме и её решению владельца.
2. В пустом проекте показать карту без слоёв, текст «В проекте пока нет данных», действие `Add DEM` и короткое описание Reference/Copy. Не запускать вычисление и не показывать псевдоданные.
3. Add DEM → выбор одного или нескольких файлов; до подтверждения пользователь видит имя, путь, размер (если доступен), тип и проверку читаемости.
4. Для каждого источника пользователь выбирает **Reference** (оставить в исходном месте) или **Copy into project**. Значение не выбирается молча по профилю; допустимый явно выбранный профиль может предварительно заполнить выбор, который пользователь всё равно видит до подтверждения. Copy показывает расчёт требуемого и доступного места; начать копирование только после проверки места и явного подтверждения. Ошибка copy оставляет исходник нетронутым и не регистрирует неполный asset как готовый.
5. После регистрации запускается DEM Preflight как операция с реальными этапами. Пока он выполняется, слой имеет состояние `Preflight running`; показ исходного DEM разрешён только после готовности безопасного viewport. Запуск обработки недоступен до завершения обязательных проверок.
6. Завершение показывает summary и все обязательные поля: формат/читаемость, band count/selected band, CRS state/definition/units, transform (включая rotation/skew), X/Y resolution, dimensions, extent, NoData/mask, dtype, NaN/Inf, валидную долю, диапазон высот, вертикальные units и compatibility, доступность/права, свободное место и оценку RAM. Unknown/absent CRS различаются. Никакой CRS не присваивается автоматически.
7. Выбор значения требует применимого решения/преобразования в отдельном потоке работы; исходный DEM не переписывается. Если показатель лишь диагностический, показывать «неизвестно/не обнаружено», а не выдумывать значение.

## 3. DEM Preflight: состояния и ошибки

| Состояние | Экран и действия |
|---|---|
| Empty | Пустой список и `Add DEM`; canvas без фальшивого слоя. |
| Loading | Имя проверяемого файла, текущий этап (open/metadata/sample checks/resource estimate), indeterminate progress, отмена только если operation безопасно отменяема. |
| Ready | Метаданные и viewport доступны; Preflight summary с временем и источником. |
| Warning | Список конкретных обнаружений: CRS absent/unknown, nodata-only, константные данные, NaN/Inf, единицы или mask, недостаток места/памяти. Слой остаётся зарегистрированным, но действия, зависящие от проверки, ограничены. У каждой записи — consequence и разрешённое действие. |
| Error | Файл повреждён/не читается/нет доступа. Не менять manifest на «готовый»; оставить остальную сессию работоспособной; показать Retry/Remove/Choose another file применительно к причине. |
| Disabled | Preflight нельзя запускать пока источник копируется, заблокирован или приложение закрывается; причина текстом. |
| Success | Не отдельная бессрочная страница: краткое подтверждение и переход к Ready с результатом. |

Preflight предупреждение не равно отказу от данных. Невалидные критические данные блокируют только действия, для которых они обязательны; пользователь видит точную причину. Любое исправление (назначение CRS, reprojection, resampling, vertical conversion, nodata repair) является отдельной явной производной операцией с provenance, никогда скрытой настройкой импорта.

## 4. Повторное открытие и потерянный источник

При Open Project приложение валидирует `project.lspx` и совместимость формата до изменения проекта. Внутренний путь разрешается относительно корня; внешний путь проверяется на доступность. При ошибке manifest или поддерживаемой версии открытие не должно частично перезаписывать файлы; сообщение указывает путь, поле/класс проблемы и recovery path.

Если один DEM отсутствует:

- проект всё равно открывается; остальные слои, результаты и их metadata видимы;
- отсутствующая строка сохраняет имя, первоначальный путь, Reference/Copy policy и время последней успешной проверки; карта показывает текстовый placeholder «Источник недоступен», не пустую белую область без пояснения;
- действие `Locate / Relink…` открывает выбор кандидата. До подтверждения сверяются читаемость, формат, CRS, размеры, transform, band и checksum; исходный путь/asset не перезаписывается на этапе выбора;
- совпадающие контрольные метаданные и checksum: пользователь подтверждает связать источник, затем проект атомарно обновляет ссылку в согласованном порядке владельцами хранилища;
- checksum отличается: явное предупреждение «Файл отличается от зарегистрированного источника», показывает expected/actual и изменившиеся известные метаданные. Действия: `Cancel` (оставить unavailable) или `Use this file anyway…` с подтверждением, причиной/диагностической записью и последующим provenance согласно утверждённой storage модели. Не интерпретировать mismatch как доказанное повреждение;
- metadata несовместимы или файл не читается: не связывать. Дать выбрать другой файл или отменить;
- повторный запуск приложения и открытие того же проекта/DEM обязаны восстановить те же слои, порядок, состояния доступности и ссылки, без повторного принудительного импорта.

Для Copy внутренний файл недоступен: показать `Locate` только если поддерживаемая схема позволяет безопасно перевязать копию; иначе предложить восстановить файл в ожидаемом project path/из резервной копии и передать вопрос владельцу storage. Не предлагать незаметно заменить внутренний asset на внешнюю Reference.

## 5. Несколько слоёв

Добавление следующего DEM проходит отдельный выбор Reference/Copy и Preflight; каждый слой получает уникальную строку и независимо восстанавливается. Ошибка одного источника не очищает canvas, selection или другие строки. Для слоёв отличающихся CRS приложение отображает исходный CRS, CRS вида и статус transformation. Если transformation недоступна/CRS неизвестен, слой остаётся в списке, но географическое наложение блокируется с объяснением. Пользователь управляет visibility, stacking order и opacity; ни одно действие представления не изменяет исходный файл. В групповых действиях пользователь видит число выбранных DEM и storage policy для каждого до подтверждения.

## 6. Закрытие проекта

`Close Project` при отсутствии несохранённых изменений закрывает проект после проверки активных задач. При изменениях предлагает `Save`, `Discard changes` или `Cancel`; Copy/import/finalization не представляются сохранёнными до безопасной границы storage-контракта. `Discard` отменяет только несохранённые изменения проекта и не удаляет исходные файлы или зарегистрированные завершённые результаты.

Если есть активная задача, сначала показать имя, реальный этап, отмену и её побочные эффекты. Доступны ожидаемые по утверждённой политике действия `Cancel task and close` либо `Keep app open`; продолжение после закрытия допустимо только если у Desktop-клиента существует явно утверждённый и проверенный lifecycle, где worker остаётся управляемым. До такого решения нельзя обещать фоновое продолжение. Не вызывать принудительное завершение как обычное закрытие. Контракт Core описывает cancel, terminal event и завершение процесса, но выбор конечной продуктовой политики остаётся открытым в OQ-23.

## 7. Acceptance criteria (Given / When / Then)

| ID | Given | When | Then |
|---|---|---|---|
| DS-01 | Новый пустой проект создан | Пользователь открывает Data Workspace | Видит пустую карту, текстовое empty state и Add DEM; Run недоступен с объяснением. |
| DS-02 | Выбирается читаемый DEM | Пользователь выбирает Reference или Copy | До сохранения политики видит выбранную опцию и последствия; исходник не перемещён и не изменён. |
| DS-03 | Copy требует больше места, чем доступно | Пользователь подтверждает импорт | Copy блокируется до записи; сообщаются нужный/доступный объём; неполный слой не маркируется Ready. |
| DS-04 | DEM читается | Preflight завершён | CRS, NoData, resolution, extent, transform, units, dimensions и validity summary доступны текстом и в отчёте. |
| DS-05 | DEM не имеет CRS | Preflight выполняется | UI помечает CRS как absent, не присваивает CRS и объясняет, какие географические действия ограничены. |
| DS-06 | Создан проект с внешним Reference DEM | Приложение закрыли и запустили снова | Проект и ссылка на DEM открываются повторно с сохранёнными слоями/метаданными. |
| DS-07 | Reference DEM перемещён/удалён | Открывают проект | Проект, доступные слои и результаты сохраняются; DEM явно unavailable; доступны Locate и Cancel. |
| DS-08 | Выбран relink-кандидат с другим checksum | Пользователь проверяет соответствие | UI показывает mismatch и отличия до записи; Cancel не меняет asset; confirm фиксирует явно выбранное продолжение. |
| DS-09 | Проект содержит несколько слоёв, один недоступен | Пользователь открывает Data Workspace | Доступные слои остаются отображены и выбираемы; отсутствующий источник не скрыт и не блокирует прочие. |
| DS-10 | Есть несохранённые правки | Пользователь выбирает Close Project | Диалог Save/Discard/Cancel; исходный DEM не удаляется ни одним вариантом. |
| DS-11 | Есть активная задача | Пользователь закрывает проект/окно | UI не обещает продолжение после выхода без утверждённой поддержки; отображает текущий этап и доступную безопасную политику. |
| DS-12 | Источник проходит CRS transformation | Он добавлен на карту | Canvas показывает исходный и целевой CRS; relink и отображение не меняют исходный DEM. |

## 8. Неподтверждённые решения

Этот сценарий использует storage модель `project.lspx` + SQLite и не изменяет её. Форма durable provenance после принятия файла с checksum mismatch зависит от существующей модели хранения и должна быть согласована с владельцем данных. Пользовательский текст/действия здесь — UX proposal; если реализация потребует дополнительных полей, событий или API, оформить Contract Change Request Agent01 до реализации. Политика закрытия окна с активной задачей остаётся OQ-23. Полный GUI E2E и reopen tests относятся к будущему Desktop implementation, не к этому документу.
